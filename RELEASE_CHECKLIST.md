# Release checklist

- [ ] Review the secret audit; rotate leaked keys and purge history where needed. Never publish .env files.
- [ ] Verify each source licence, review quotations and derived data, and apply exclusions or obtain permission. .gitignore does not remove tracked files or history; inspect the whole public repository and archive.
- [ ] Preserve cleared code, prompts, manifests, seeds and sample specifications; check remaining artifacts for restricted text and personal paths.
- [ ] Review and commit the release files; handle the author's writing and slides as intended.
- [ ] Fill in the release date in CITATION.cff and verify metadata.
- [ ] Make the repository public only after reviewing all branches, tags and history, including material outside this release.
- [ ] Enable Zenodo GitHub integration, create the release tag and verify the archive and DOI.
- [ ] Paste the DOI into the paper's refs.bib entry ragab2026code.
